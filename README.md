# ChronoStyle — учебный интернет-магазин

Одностраничный демонстрационный сайт витрины часов и настольных календарей. Реализован на HTML5, CSS3 и JavaScript без сторонних библиотек.

## Структура проекта

```text
chronostyle/
├── index.html
├── style.css
├── script.js
├── 404.html
├── robots.txt
├── sitemap.xml
├── .htaccess
├── README.md
└── assets/
    └── favicon.svg
```

## Возможности

- адаптивная верстка для компьютеров, планшетов и телефонов;
- меню-якоря по разделам страницы;
- каталог часов и настольных календарей;
- фильтрация по категориям и сортировка по цене/названию;
- карточки товаров и модальное окно подробного просмотра;
- добавление товаров, изменение количества и удаление из корзины;
- подсчет суммы заказа;
- сохранение корзины в `localStorage` под ключом `chronoCart23`;
- демонстрационное оформление заказа без оплаты;
- HTML-валидация формы обратной связи;
- уведомления об действиях пользователя;
- страница 404, `robots.txt`, `sitemap.xml` и пример конфигурации Apache.

## Запуск локально

1. Распакуйте архив.
2. Откройте `index.html` в браузере.

Для проверки через локальный HTTP-сервер из каталога проекта можно выполнить:

```bash
python -m http.server 8000
```

После этого откройте `http://localhost:8000`.

## Публикация

Загрузите файлы проекта в корневой каталог сайта на хостинге. Перед публикацией замените `https://example.com/` в `robots.txt` и `sitemap.xml` на фактический домен.

Файл `.htaccess` рассчитан на Apache и требует включенного `mod_rewrite`. Не используйте его на хостинге с Nginx без переноса правил в конфигурацию сервера.

## Важные ограничения учебного проекта

- Каталог хранится в JavaScript, серверной базы данных нет.
- Корзина хранится только в браузере пользователя.
- Оформление заказа демонстрационное: платёж, отправка заказа и сохранение на сервере не выполняются.
- Форма контактов не отправляет сообщения на сервер.
- HTTPS заработает только после настройки домена и установки действующего SSL/TLS-сертификата на хостинге.
- `robots.txt`, `sitemap.xml`, перенаправления и заголовки безопасности требуют проверки после размещения на реальном сервере.
- Для промышленного магазина потребуются серверная проверка данных, обработка заказов, защита от злоупотреблений, политика конфиденциальности и безопасная платёжная интеграция.
